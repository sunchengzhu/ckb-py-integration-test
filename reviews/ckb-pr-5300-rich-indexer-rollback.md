## 变更说明

- 目的与实际改动：PR 声明过滤区块可形成空交易 ID 列表，PostgreSQL 拒绝其中的 `IN ()`，因此应保持这类区块可回滚。代码在 `reset_spent_cells` 的空列表分支提前返回，并增加 SQLite 函数级回归。只有这个恢复函数跳过查询，整个回滚仍读取、删除并提交数据库状态；未发现 PR 说明与 diff 冲突。 / The PR targets PostgreSQL rejection of an empty-ID query when rolling back filtered blocks. Code returns early in the empty branch of reset_spent_cells and adds a SQLite function test. Only that function skips its query; the whole rollback still reads, deletes and commits database state. No description/diff conflict was found.
- 前后行为：旧实现对空列表仍生成 spent-cell reset 查询，可能使 PostgreSQL 回滚中断；新实现跳过该 reset，继续清理旧索引区块并跟随新主链。新增上游单测不代替外部 PostgreSQL 验证，本轮未运行其命令。 / Previously, the empty-list reset could interrupt PostgreSQL rollback. The change skips that reset and permits remaining block cleanup and new-chain indexing. The upstream unit test does not replace external PostgreSQL verification; its command was not run here.
- 直接/间接影响：直接影响过滤区块的回滚；必须保持非空列表下的 spent 恢复与旧记录删除。连续/混合回滚、后续交易及正常重启是相邻回归。PostgreSQL 与 SQLite 共用 Case ID；SQLite 结果不能替代 PostgreSQL。查询限定 `group_by_transaction=true`；旧交易移除只指索引查询，不要求节点删除旧分叉原始记录。 / Direct impact is filtered-block rollback. Nonempty resets and stale-record removal must remain correct. Consecutive/mixed rollback, subsequent transactions and normal restart are adjacent regressions. PostgreSQL and SQLite share IDs; SQLite cannot replace PostgreSQL. Queries use grouped transactions, and removal means removal from the index, not deletion of raw fork data.
- 未读材料：本轮未完整分析 cell filter、交易池叠加、数据库中断、强制崩溃、数据库迁移、非分组分页及性能路径，也未做整个 PR 或版本的验收。 / Cell-filter, txpool-overlay, outage, crash, migration, ungrouped-pagination and performance paths are not fully analysed; this is not whole-PR or release acceptance.
